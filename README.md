only release documentation and binary assets; application source code,
credentials and customer configuration are kept elsewhere.

## Verify and update

1. Select the approved package for the same environment in the web application.
   Check the ZIP hash against the value in its release notes:

   ```powershell
   Get-FileHash .\VixitSignalAgentSetup-0.4.26.zip -Algorithm SHA256
   ```

2. Extract the ZIP. Compare the EXE hash with its included checksum and confirm
   the manifest's version, production channel, source commit and API URL.
3. Follow the package's `README-INSTALL.txt`. The EXE is the installer;
   the current ZIP does not contain the old service-install PowerShell scripts.
4. For an update, stop only the service being updated and preserve its
   configuration, protected token, binding and durable queues. Do not generate
   a new identity just to update.
5. After the authorized local installation, verify the Windows service's
   reported version and heartbeat in the web. Publication alone does not install
   or restart a service or configure hardware.

SHA-256 verifies bytes, not publisher identity. This Windows EXE is
`NotSigned`; consult support about an unknown-publisher warning.
Check Authenticode separately. Android signing is a separate identity.

## Separate channels and packages

Windows production uses service `VixitSignalAgent`, PROD Manager and
`https://rfid.vixit.net`. Windows staging uses prerelease tags, a distinct
installer/service/ProgramData and `https://staging.rfid.vixit.net`.
Never copy credentials, bindings, configuration or queues between channels.

C72 APKs use separate `c72-*` tags and signing identities. Obtain their approved
environment-specific link and metadata from the application; the Windows latest
release is not an APK download.

Older releases remain immutable on the [Releases page](https://github.com/ddacol24/rfid-edge-hub-agent-releases/releases).
GitHub's autogenerated source archives contain only README/CHANGELOG.
They are documentation archives, not installable agent packages.

Never publish tokens, real configuration, customer data or hardware credentials.
